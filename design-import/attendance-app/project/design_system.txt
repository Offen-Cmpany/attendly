Student-first attendance for Kerala higher education



Prepared for Salahudheen



April 2026







1. Overview



Attendly is an attendance and academic-life app for students in Kerala higher-education institutions. It exists because the incumbent (ezygo.app) is built for the institution that writes the cheque, not the student holding the phone. Our wedge is three-fold:




A student-first UI that answers the one question every student asks daily: am I safe for exam eligibility?




Live updates aggregated from university public sources (KTU, Calicut University, MG, Kerala) — notifications, results, timetables, circulars.




A native community layer inside the app, so clubs and chapters (IEEE, CSI, MuLearn, NSS, arts, hackathon teams) stop living in WhatsApp chaos and plug into duty-leave workflows.



This document is the single source of truth for how Attendly looks, feels, and behaves across iOS, Android, and web.








2. Design principles




Answer the question before the student asks it



A student doesn&apos;t want a list of subjects with percentages. They want to know: am I safe, and how many hours can I skip? Every screen should prioritize decisions over data.




Institutional on the outside, youthful on the inside



Primary blue signals trust to the college administration buying the license. Coral accents, streaks, and celebration moments give the student the Duolingo-style dopamine loop that keeps the app open.




Offline-first is not optional



Indian campus Wi-Fi is unreliable and lab networks are worse. Every write action (mark attendance, submit leave, RSVP to event) must queue locally and sync when a connection returns.




Malayalam is a first-class language



Not an afterthought. All UI strings, notifications, and reports must be translatable, and the font stack must render Malayalam without fallback artifacts.




One tap is better than two



Faculty marking attendance should default to all-present, then tap only absentees. Students checking attendance should see the number on the home screen, not three menus deep.

4. Typography




4.1 Font stack



Primary: Inter (Latin) + Manjari (Malayalam). Both are open-source, free for commercial use, and render cleanly at small sizes on low-density displays — critical for students on budget Android phones.



font-family: &apos;Inter&apos;, &apos;Manjari&apos;, -apple-system, BlinkMacSystemFont, sans-serif;



Monospace (for register numbers, codes, hex): JetBrains Mono.




4.2 Type scale



Two weights only: 400 regular, 500 medium. No 600 or 700 — they read heavy against Attendly&apos;s clean surfaces.

4.3 Casing rules




Sentence case everywhere. Never Title Case. Never ALL CAPS in body or headings.




The only permitted uppercase: eyebrow labels above cards (e.g. OVERALL ATTENDANCE) at 11px with 0.3px letter-spacing.




Subject names retain their original casing (e.g. &apos;Compiler Design&apos; stays as the university registers it).







5. Spacing, radius, elevation




5.1 4-point grid



Every margin, padding, and gap is a multiple of 4. Period. This keeps iOS, Android, and web layouts consistent and makes design reviews mechanical instead of subjective.




xs = 4  · icon padding, tight clusters




sm = 8  · between related elements, chip internal padding




md = 12 · card internal gaps




lg = 16 · card padding, between cards in a list




xl = 24 · section breaks




2xl = 32 · screen top padding, major section separators




5.2 Corner radius




6  · input fields, small chips




8  · buttons, secondary cards




12 · primary cards, list rows




16 · hero attendance card, modals




999 · pills and status badges only




5.3 Elevation



Attendly is flat. No drop shadows. Depth is communicated through surface color (white cards on off-white background) and 0.5px borders. The only exception: a 4px focus ring on interactive elements for keyboard accessibility.



--focus: 0 0 0 4px rgba(55, 138, 221, 0.2);







6. Core components




6.1 Buttons



Four variants. No more. If you need a fifth, you are solving the wrong problem.




Primary — blue-600 background, white text. The default action on any screen.




Secondary — transparent background, blue-600 border and text. Complementary actions.




Accent — coral-400 background, white text. Reserved for emotional or attention-grabbing actions (request leave, RSVP).




Ghost — no background, no border, muted text. Cancel and dismiss actions only.



Sizing: 40px height on mobile, 36px on web. Padding 10px 18px. Border-radius 8. One button per screen in the primary variant — competing primaries create decision paralysis.




6.2 Status pills



The visual vocabulary of attendance. Always in sentence case, always with a leading dot-icon for the three attendance states, always pill-shaped (border-radius 999).



● Safe · 82%       (safe-bg + safe-fg)



● Watch · 76%      (warn-bg + warn-fg)



● Risk · 71%       (risk-bg + risk-fg)



Duty leave          (blue-50 + blue-900)



🔥 7 day streak    (coral-50 + coral-900)




6.3 Inputs



0.5px border in gray-200 default, blue-400 on focus with a 4px focus ring. Height 40 on mobile. Label sits above the input in caption size, never placeholder-only — floating-label patterns fail for users typing in Malayalam.




6.4 Progress bar



8px tall, border-radius 999, gray-50 track. The fill color maps to the attendance state automatically: green-600 at ≥80%, amber-400 at 75–79%, coral-400 below 75%. This is the core semantic feedback loop in the app.




6.5 Cards




Default card — white background, 0.5px gray-200 border, radius 12, padding 16.




Hero card — blue-800 background, white text, radius 16, padding 20. Used exclusively for the attendance summary on the home screen.




Metric card — blue-50 or coral-50 background, no border, radius 12, padding 12. Used in 2-up grids for streak and daily stats.




Notification strip — tinted background with a 3px left border in the same hue. Rounded only on the right edge.




6.6 Bottom navigation



Four tabs. Home, Timetable, Communities, Profile. Each tab is a 24px icon plus a 10px label. Active tab has blue-50 background pill and blue-600 label. Tabs are the skeleton of the app — adding a fifth tab later costs more than shipping the wrong feature.







7. Screen inventory



The screens below are the complete v1 surface area. Anything not listed here is v2 or later.




7.1 Student screens




Home — hero attendance card, today&apos;s classes, university strip, community strip, bottom nav.




Subject detail — hour-by-hour attendance log, percentage trend, &apos;can skip X more hours&apos; calculator.




Timetable — weekly grid, tap-through to subject detail, mark-present-later affordance for offline classes.




Leave request — reason selector (medical, duty leave, personal), date range, attach proof, submit-and-track status.




Communities list — all communities at your college, joined and discoverable.




Community detail — about, events, members, posts. Community secretaries get an extra &apos;Manage&apos; surface.




Event detail — date, location, RSVP, &apos;request duty leave for this event&apos; action.




University updates — feed of KTU / Calicut / MG / Kerala notices, filterable by tag (exam, result, holiday, circular).




Profile — register number, semester, attendance goal, notification prefs, language toggle (English / Malayalam).




7.2 Faculty screens




Home — today&apos;s teaching schedule, attendance-pending count, one-tap &apos;mark all present&apos;.




Mark attendance — class roster with default-present toggle, bulk absent selection, save offline.




Class detail — aggregate percentage, at-risk students flagged in red, message-whole-class action.




Leave approvals — queue of pending student leaves, one-tap approve with notes.




Reports — course attendance export (CSV, PDF), attainment report triggers for the institution.




7.3 Admin / HoD screens




Institution dashboard — overall attendance, department-wise breakdown, at-risk cohort.




Community management — approve new communities, assign secretaries, review event duty-leave requests.




Accreditation exports — the OBE reports Ezygo built its entire product around. Attendly generates them quietly in the background so admins never wonder if v1 is &apos;serious enough&apos; for NAAC.







8. Microcopy &amp; tone




8.1 Voice



Attendly speaks like a helpful senior, not an institution. Direct, warm, never patronizing. Never uses the word &apos;kindly&apos;. Never says &apos;please note&apos;. Never apologizes for its own product (no &apos;sorry for the inconvenience&apos;).




8.2 Attendance framing



Always frame attendance as a decision, not a judgment.




Instead of: &apos;Your attendance is 82%&apos;




Write: &apos;You can skip 14 more hours and stay eligible.&apos;




Instead of: &apos;Warning: low attendance&apos;




Write: &apos;You&apos;ll need to attend the next 4 classes to stay above 75%.&apos;




8.3 Empty states




No classes today: &apos;Free day. Enjoy it.&apos;




No notifications: &apos;All quiet on the university front.&apos;




No events: &apos;Nothing on the community calendar yet — check back or start one.&apos;




8.4 What we don&apos;t do




No emoji in system messages (user-generated content is free to use them).




No gamification language around attendance itself (&apos;level up!&apos; is cheap). Streaks are for consistency, not attendance percentage.




No &apos;beta&apos; tags, no &apos;coming soon&apos; in shipped UI. If it isn&apos;t ready, it isn&apos;t visible.







9. Accessibility




Minimum contrast 4.5:1 for body text, 3:1 for large text. Every combination in this doc has been checked.




Minimum tap target 44×44pt on mobile.




Never rely on color alone — attendance state is always color + label (&apos;Safe · 82%&apos;).




Full VoiceOver and TalkBack support. Hero attendance card reads as: &apos;Overall attendance 82 percent. Safe. You can skip 14 more hours.&apos;




Dynamic Type support on iOS. Minimum supported: Large; maximum: xxxLarge.




Reduced-motion respect: streak flame doesn&apos;t animate if prefers-reduced-motion is set.




10. Platform notes




10.1 iOS



SF Pro is forbidden — Inter is the brand font and must ship embedded. Use native UIKit/SwiftUI navigation patterns (back chevron, tab bar) but skin them with Attendly colors. The status bar mimics iOS natively, don&apos;t draw your own.




10.2 Android



Material You dynamic color is disabled — we own the palette, not the OS. Use Material components for tap ripples and sheet behaviors. Edge-to-edge layout with Attendly&apos;s off-white as the root background.




10.3 Web



Desktop web is the faculty and admin surface. Mobile web is a fallback for students who can&apos;t install. Keyboard navigation and focus rings are mandatory. Max content width 1200px, sidebar navigation instead of bottom nav on screens wider than 768px.
